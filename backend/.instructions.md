# Backend Instructions — FastAPI & SQLAlchemy

Specific rules for the `backend/` directory of Timelyna.

## 🏗 Architecture: Route -> Service -> Repository
1. **Repository (`app/repositories/`)**:
   - Single responsibility: Database CRUD operations.
   - Use SQLAlchemy 2.x async API (`await session.execute(...)`).
   - No business logic or complex validation here.
2. **Service (`app/services/`)**:
   - Orchestrates repositories and handles business logic.
   - Performs validations that require DB state.
   - Throws custom domain exceptions.
3. **Router (`app/api/v1/`)**:
   - Handles HTTP requests and responses.
   - Uses Pydantic schemas for input/output.
   - Calls service methods.
   - Maps exceptions to HTTP errors.

## 🐍 Python Style & Rules
- **Formatting:** Follow PEP 8 (black-style).
- **Types:** Always use type hints for function arguments and return values.
- **Pydantic:** Use Pydantic v2. Use `model_validate` instead of `from_orm`.
- **SQLAlchemy:** 
  - Use `Mapped` and `mapped_column` for models.
  - Use `select()` and `ScalarResult` for queries.
  - Always handle sessions asynchronously.

## 🧪 Testing
- Write tests in `backend/tests/`.
- Use `pytest` with `pytest-asyncio`.
- Use `httpx.AsyncClient` for integration tests.
- Mock external services (Email, S3).

## 🔒 Security
- Use `Depends(get_current_user)` or `Depends(get_current_active_user)` for protected routes.
- Check user permissions in services.
- Never return sensitive data (hash passwords, emails in public lists).
